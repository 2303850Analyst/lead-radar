# Настройка Geoapify Places для LeadRadar

Geoapify добавлен в `0.2.0` и остаётся единственным live-источником
`0.4.0-alpha.1`. Приложение использует четыре API surface:

- Geocoding API преобразует введённый город или адрес в координаты;
- Autocomplete подтверждает provider-native leaf для подписанного recovery arm;
- Places API ищет POI заданных категорий в выбранном радиусе;
- Place Details дополняет bounded набор найденных POI.

Ключ передаётся Geoapify только серверным маршрутом LeadRadar. Он не должен
попадать в React-компоненты, HTML, browser storage, логи или Git.

## 1. Выпустить ключ

1. Откройте [Geoapify MyProjects](https://myprojects.geoapify.com/).
2. Создайте проект `LeadRadar` или откройте существующий.
3. В разделе **API Keys** создайте отдельный ключ для локальной разработки.
4. Убедитесь в разделе **Billing**, что выбран нужный тариф.
5. Контролируйте расход во вкладке **Statistics**.

Ключ, однажды опубликованный в чате, скриншоте, issue или логе, считается
раскрытым. Локальная интеграция была проверена текущим ключом, но перед любым
внешним deployment его необходимо удалить в MyProjects и выпустить новый:
чужие запросы могут исчерпать дневную квоту и отключить рабочий поиск.

## 2. Настроить локальное окружение

В корне проекта создайте `.env.local` на основе `.env.example`:

```env
GEOAPIFY_API_KEY=новый_ключ_из_MyProjects
SEARCH_PROVIDER=geoapify
GEOAPIFY_PLACES_LIMIT=100
GEOAPIFY_DETAILS_LIMIT=20
SITE_URL=http://localhost:3000
```

Не используйте имя `NEXT_PUBLIC_GEOAPIFY_API_KEY`: переменные с таким префиксом
могут попасть в клиентский bundle. `.env.local` исключён из Git.

Если нужен гарантированно синтетический режим, установите:

```env
SEARCH_PROVIDER=demo
```

## 3. Перезапустить и проверить

После изменения окружения пересоберите проект и запустите локальный production
server:

```powershell
npm run build
npm run start
```

Dev-сервер слушает только `127.0.0.1`. Не открывайте маршрут поиска во внешнюю
сеть без аутентификации и серверного ограничения запросов: иначе чужие запросы
смогут расходовать дневную квоту Geoapify.

Затем откройте:

```text
http://localhost:3000/api/search
```

Health-ответ должен показывать активный Geoapify provider и наличие его
серверной конфигурации, но никогда не возвращать сам ключ.

После этого выполните один небольшой поиск через интерфейс, например по Москве
с радиусом 3–5 км. Полный production build и автоматические тесты не заменяют
проверку реального ответа провайдера.

Контрольный live smoke test 2026-08-15 завершён успешно: геокодирование и Places
вернули данные, а Place Details был получен для всех 20 карточек контрольной
выборки. В ней телефон присутствовал у 14, email у 11 и сайт у 15 карточек.
В финальном прогоне получено 99 лидов: у 5 карточек с Place Details URL не был
указан, а 79 карточек без Details оставлены в статусе «данные не проверены» и не
считаются автоматически компаниями без сайта. Ключ и полные raw-ответы не
сохранялись в Git или документации. Эти числа подтверждают работоспособность
транспорта и конкретной выборки, но не полноту рынка.

## Как трактуется поиск

Places API работает прежде всего по иерархическим категориям, а не как
универсальный полнотекстовый каталог. Для текущего сценария складов и
фулфилмента основной запрос использует `office.logistics` и `rental.storage`.
Широкая категория `building.industrial` намеренно исключена из live-поиска MVP:
в контрольной выборке её безымянные промышленные геометрии вытесняли карточки
организаций. Если эта категория понадобится для отдельного исследования, её
следует запускать самостоятельным batch и не смешивать с основной выдачей.

Следствия:

- результат — обнаруженная выборка, а не полный реестр организаций;
- нулевой ответ не доказывает отсутствие компаний в регионе;
- категория источника может быть шире пользовательского запроса;
- полнота телефонов, сайтов и социальных сетей зависит от исходных открытых
  данных;
- отсутствие сайта означает только «URL не указан в ответе источника».

Geoapify документирует обязательную категорию, пространственный фильтр,
пагинацию через `limit`/`offset` и максимум 500 объектов в одном ответе:
[Places API](https://apidocs.geoapify.com/docs/places/).

## Бесплатный тариф и атрибуция

На 2026-08-15 Free plan включает 3 000 кредитов в день, до 5 запросов в секунду,
не требует банковской карты и допускает ограниченное коммерческое
использование. Запрос Places до 20 результатов стоит 1 кредит; при большем
`limit` добавляется 1 кредит за каждые следующие 20 возвращённых объектов.
Geocoding-запрос стоит 1 кредит. Перед рабочим запуском перепроверьте
[актуальный тариф](https://www.geoapify.com/pricing/) и
[стоимость endpoint](https://www.geoapify.com/pricing-details/).

При текущих значениях для фулфилмента один поиск обычно тратит до 26 кредитов:
1 на geocoding, до 5 на один Places-запрос с лимитом 100 и до 20 на Place
Details. Фактический расход зависит от категорий и количества карточек;
источником истины остаётся вкладка **Statistics** в MyProjects.

При Free plan обязательны видимая атрибуция Geoapify и атрибуция OpenStreetMap.
Требования описаны в
[Terms and Conditions](https://www.geoapify.com/terms-and-conditions/). В
интерфейсе должна сохраняться ссылка `Powered by Geoapify` и указание
`© OpenStreetMap contributors`.

## Ошибки и квота

- `400` означает некорректный запрос или неподдерживаемые параметры;
- `422` означает, что для вида бизнеса ещё не настроена категория MVP;
- `401`/`403` — недействительный ключ или ограничения ключа;
- `429` — исчерпан rate limit или квота;
- `5xx`/timeout — временная ошибка провайдера.

LeadRadar не должен подменять ошибку live-поиска синтетическими карточками:
пользователь увидит ошибку источника и сможет повторить запрос. Для production
нужны мониторинг квоты, ограничение частоты запросов и отдельные ключи для dev и
production.

## Черновик будущего fallback

В `0.4.0-alpha.1` активен ровно один live-провайдер — Geoapify. Автоматический fallback
ещё не реализован. Архитектура должна позволить позднее добавить адаптеры
Overpass, Overture или договорной источник без изменения публичного
`POST /api/search`.

Будущее правило failover:

1. основной provider вызывается с таймаутом и ограниченным числом повторов;
2. резерв вызывается только при timeout, `429` или `5xx`;
3. `400`, нулевой результат и нерелевантная категория не запускают резерв;
4. источник, внешний ID и время наблюдения сохраняются для каждого поля;
5. синтетические demo-данные никогда не являются live-fallback;
6. объединение результатов нескольких источников — отдельный режим aggregation,
   а не обработка ошибки.

Перед реализацией каждого нового адаптера отдельно проверяются лицензия на
хранение и экспорт, категории, стоимость, лимиты, правила атрибуции и
дедупликация.
