# LeadRadar v0.4.0-alpha.1 — production search live canary

Дата проверки: 2026-08-20

Решение: **FAIL для quality gate Issue #11; NO-GO для production v0.4.0 и
внешнего SLA**.

Проверка прошла через фактический production NDJSON-orchestrator с реальными
Kimi и Geoapify и отдельным literal baseline. Этот versioned отчёт содержит
только агрегаты, версии и checksum. Тексты запросов, списки лидов, provider
identities, контакты организаций, API-ключи, prompts, reasoning и raw
model/provider responses в Git не записывались.

Предварительный прогон с переменным знаменателем был признан методологически
некорректным и не используется. Текущий результат получен повторно после
перехода на fixed-k Precision@10, одноразовую cross-query дедупликацию и учёт
каждой production-попытки.

Ручная оценка была консервативной, но не слепой: reviewer видел раздельные
semantic и baseline списки. В локальный review endpoint передавались только
нормализованные transient-кандидаты; обратно отправлялись номера релевантных
позиций. Внутри одного запуска provider identities связывались одноразовым
session-salted HMAC и удалялись до формирования отчёта. Это позволяет считать
уникальные организации между запросами, не сохраняя стабильный псевдоним лида.

`Precision@10` использует фиксированные 120 позиций: отсутствующий результат
считается нерелевантной позицией. `Precision among retrieved` приведён только
как диагностика и не заменяет quality gate.

## Provider-native category hints

Canary явно включал экспериментальный resolver, тогда как production default
остаётся `GEOAPIFY_CATEGORY_HINTS_ENABLED=false`.

| Статус | Случаи |
|---|---:|
| `not_needed` | 9 |
| `no_match` | 1 |
| `degraded` | 0 |
| `resolved` | 2 |

Выполнено три provider-native category-resolution запроса; два дали
верифицированную leaf-category для runtime fallback, один не дал совпадения.
Ни один hint не изменил `SemanticIntentV2` или подписанный `SearchPlan`.
Механизм остаётся выключенным по умолчанию: пустой, неизвестный или недоступный
hint безопасно деградирует к server-owned fallback и не становится relevance
truth сам по себе.

## Решение

Функциональный open-vocabulary путь подтверждён: Kimi strict-schema rate,
provider executability, deadline, cross-query uniqueness и safety gates
прошли. Business quality gate не пройден: fixed-k Precision@10 равен `0.7500`
при требовании `0.85`.

Issue #11 нельзя закрывать, а Issue #12 и release/tag `v0.4.0` остаются
заблокированными. Следующий шаг — улучшить provider grounding и стратегию
fallback для редких ниш либо добавить юридически совместимый второй источник,
после чего повторить тот же замороженный canary без изменения порогов.
Encoder p95 также должен быть снижен до целевых 20 секунд. Выборка из 12
сценариев не обосновывает внешний SLA даже после будущего PASS.

## Воспроизведение

Команда требует внешние server-side Kimi и Geoapify keys и явно расходует их
квоту. Top-level script обязательно пересобирает production worker перед
запуском:

```powershell
$env:RUN_SEARCH_LIVE_CANARY="1"
npm run canary:search:live
Remove-Item Env:RUN_SEARCH_LIVE_CANARY
```

Canary завершает процесс ненулевым кодом при нарушении hard gate. Рабочий JSON
summary создаётся только в игнорируемом `work/evaluations/`; публикуемый файл
выше переносит из него лишь агрегаты.
