# LeadRadar

Текущая версия: **0.1.0**

LeadRadar — локальный MVP для обнаружения потенциальных B2B-клиентов среди
малозаметных и слабо оцифрованных компаний. Пользователь задаёт основной и
смежные запросы, географию и свои услуги, а приложение формирует объяснимую
выборку организаций.

LeadRadar — **discovery-система, а не полный реестр рынка**. Поисковый источник
возвращает релевантную выборку и не гарантирует, что найдены все компании.

## Возможности версии 0.1.0

- создание поискового задания на русском языке;
- основной запрос, смежные запросы и исключения;
- четыре представления: поиск, таблица, карта и карточка лида;
- фильтрация, сортировка, пагинация и CSV для demo-данных;
- статусы, заметки и локальное сохранение demo-поиска;
- серверный `GET/POST /api/search`;
- детерминированный demo-режим без ключа;
- подготовленный, но не проверенный live-адаптер API Яндекса;
- защита от случайного включения live UI одним только API-ключом.

## Быстрый запуск

Требования: Node.js `>=22.13.0` и npm.

```powershell
npm install
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000). Сервер привязывается к
`0.0.0.0`, поэтому страница доступна и через `127.0.0.1`.

Без дополнительных настроек приложение использует только синтетические
demo-данные.

## Проверка проекта

```powershell
npm run lint
npm test
```

`npm test` собирает production-версию и проверяет SSR, health endpoint,
demo-поиск, валидацию, имя пакета и версию API.

## API приложения

### `GET /api/search`

Возвращает health, версию и активный режим.

```json
{
  "status": "ok",
  "service": "LeadRadar Search API",
  "version": "0.1.0",
  "mode": "demo",
  "yandexConfigured": false,
  "yandexKeyConfigured": false,
  "yandexLiveUiEnabled": false
}
```

`yandexConfigured` становится `true` только когда одновременно присутствует
ключ и явно включён экспериментальный live UI.

### `POST /api/search`

Обязательны `primaryQuery` и `location`. Радиус по умолчанию — 15 км.

```json
{
  "description": "Компании, которые оказывают услуги фулфилмента",
  "primaryQuery": "Фулфилмент",
  "relatedQueries": [
    "Ответственное хранение",
    "Складские услуги",
    "Комплектация заказов"
  ],
  "excludeQueries": ["Камеры хранения", "Аренда гаражей"],
  "location": "Москва",
  "radiusKm": 15,
  "offer": "Оцифровка обработки заявок и внедрение CRM",
  "services": ["Создание сайта", "CRM", "Автоматизация"]
}
```

Ответ содержит параметры запроса, сводку и массив `leads`. Ошибки валидации
возвращаются с HTTP 400. Ошибка внешнего провайдера в экспериментальном режиме
возвращается с HTTP 502 и не подменяется демоданными.

## Реальный API Яндекса

Реальный API технически поддержан адаптером, но **не считается готовой функцией
версии 0.1.0**. Он не был проверен реальным ключом.

Текущий demo-интерфейс сохраняет результат в браузере, меняет порядок по
собственному score, экспортирует CSV и использует OpenStreetMap. Опубликованные
условия Яндекса могут запрещать такой процесс для данных API Поиска по
организациям. Поэтому одного `YANDEX_MAPS_API_KEY` недостаточно: по умолчанию
продолжает работать demo-режим.

Следующая задача — изолированный transient smoke test без сохранения полного
ответа. Пошаговый план: [`docs/yandex-live-test.md`](docs/yandex-live-test.md).

До письменного подтверждения Яндекса не устанавливайте
`YANDEX_LIVE_UI_ENABLED=true` для рабочего использования.

## Ограничения

- До восьми поисковых терминов на одно задание.
- До 50 объектов на термин; пагинация ещё не реализована.
- Круговой радиус от 0,5 до 250 км; произвольный полигон отсутствует.
- Исключения применяются простым поиском по названию, адресу и категории.
- Отсутствие URL означает только «сайт не указан в карточке источника».
- Сайты и социальные сети в live-режиме не проверяются.
- Scoring является эвристикой, а не прогнозом сделки.
- Для постоянной базы, enrichment, экспорта и CRM нужен источник или лицензия,
  разрешающие обработку и хранение данных.
